# 登记表导入台(两版 CSV)

登记端导出两版 CSV,本服务负责接收、辨版本、按映射转换发布、拒收重跑,并提供行级来历查询。

## 两版格式

| 版本 | 列 | 编号形态 |
| --- | --- | --- |
| 旧版 v1 | `编号,姓名,单位` | 数值,如 `123` |
| 新版 v2 | `编号,姓名,单位,部门` | 保留前导零的字符串,如 `0123` |

## 关键设计选择

- **辨版本**:接收进程按表头辨别(有无`部门`列);表头缺必需列(`编号/姓名/单位`)整批拒收,不留批次。
- **保留原列**:统一为超集结构 `编号/姓名/单位/部门`。旧版行部门为空;旧版再次导入**不会**清空新版已提供的部门。
- **身份归一**:编号统一去前导零作为人员主键 —— `0123`(新版)与 `123`(旧版)是同一人,交替导入不会认成两人;原始编号保留在行级来历里。非纯数字编号拒收。
- **发布门槛**:转换进程只在单位命中映射表时发布,否则拒收并写明原因;已发布行不因后续映射修订而回溯(来历里保留当时的映射修订号)。
- **重跑**:新增/修订映射后,所有拒收行按当前映射重跑;每次处理尝试都记入行级来历。

## 运行

```bash
node server.js        # 读取 PORT(默认 3000),绑定 127.0.0.1
PORT=8080 node server.js
```

打开 `http://127.0.0.1:3000`,页面预置合成样例,可依次操作:

1. **导入两版登记表**:分别导入或点「交替导入两版(旧 → 新 → 旧)」。`质检组`、`运输队` 未预置映射,对应行会被拒收;`123` 与 `0123` 在名册里归并为同一人。
2. **修订一处映射重跑**:在映射区填 `质检组 → 质量部` 保存,拒收行自动重跑并发布;再补 `运输队 → 物流部` 同理。
3. **查看行级来历**:点击「行级处理结果」中任意一行,查看来源批次、版本、原始值、所用映射修订号与全部处理尝试。

业务结果区带 `data-evidence-result` 属性,来历面板带 `data-evidence-provenance` 属性,便于核对操作前后内容。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态(映射、批次、行、名册、统计) |
| POST | `/api/import` | `{csv, name}` 导入,自动辨版本 |
| POST | `/api/mappings` | `{alias, canonical}` 保存映射并自动重跑拒收行 |
| POST | `/api/rerun` | 手动重跑全部拒收行 |
| GET | `/api/rows/:id` | 行级来历(含批次与处理尝试) |

## 测试

```bash
node --test
```

覆盖:CSV 解析(引号/CRLF/BOM/未闭合)、版本辨别、编号归一、映射发布与拒收、交替导入身份归一、旧版不清空部门、拒收重跑、已发布不回溯,以及 HTTP 层的正常流程与 400/404/422 异常。
